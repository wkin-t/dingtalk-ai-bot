# dws 会话审查问题修复计划

范围：修复本会话 CR 确认的四项问题，保持钉钉仅依赖 dws 的历史来源和现有模型配置。

1. 下载安全（`app/http_safe.py`）：按 origin 限制自定义请求头；跨 origin 后不再恢复原鉴权头；拒绝 HTTPS 降级。Cookie 按原 URL 域名匹配且仅同 origin 延续，防止同 IP 不同主机之间串 Cookie。保留逐跳 DNS/IP 校验及下载体积限制。下载异常仅返回固定类别和可选状态码，不包含 URL、响应正文或底层异常文本。
2. 文档错误边界（`app/dws_files.py`）：提供固定下载失败说明，不把原始异常放入模型输入。测试实际文档读取入口，确认签名 query、用户信息及底层异常不进入 note/prompt。
3. 媒体预算（`app/dws_context.py`）：图片上限仅约束成功读取的图片；文档读取使用独立、有界预算。保持原消息归属、可见窗口、clear 过滤、显式引用邻居和图片总量上限。
4. 数据库迁移（`app/database.py`）：只忽略 MySQL 明确的重复列1060、重复索引1061；其他异常进入初始化已有失败路径，不提交成功。测试列、索引异常与已有 schema 的幂等启动。

执行：先对设计做独立攻击面审查；媒体和数据库任务分别由独立子代理负责生产代码和既有测试文件，主线程负责下载及文档错误边界；均执行红→绿验证，禁止接触真实凭据或发送钉钉消息。主线程汇总后编译、运行全量 tests、更新 README/DEPLOY 相关限制说明，再由全新代理做提交门禁审查。

交付：仅提交明确列出的源码、测试和相关文档；不提交本地工具目录、凭据和临时文件。沿用用户已有提交部署授权。部署前核验服务器当前版本和三个容器，保存镜像/源码回滚点；构建完成后逐个切换目标应用，检查健康和运行代码，并在容器中运行不发送消息的确定性回归探针。真实群聊接话与图片识别必须与本地 Mock 验证分开报告。

设计审查处置：
- 文档解析异常也会进入 note，纳入固定错误摘要和回归测试，CLI 失败正文不透传。
- 图片、文档分别累计且单独限制候选尝试，图片满额不阻断文档；显式引用与历史共享图片总上限。
- MySQL DDL 非事务，失败可能留下已新增的列；不承诺事务回滚，补充部分迁移后的幂等重试测试与部署说明。既有 usage_stats 表的任意历史 schema 差异属于本次四项 CR 之外，保持原样，不新增无依据的迁移。
- 实现审查补强：同 origin Cookie 在 DNS 地址变化时仍延续；CLI 异常转换为固定资源失败状态且保留取消语义；URI 形态文件名只使用路径末段；失败图片资源也计入 helper 尝试上限；单条历史消息可读多张图，引用邻居仅补全实际选中的条目。

完成标准：对应回归测试和全量测试通过；独立提交门禁无阻断；提交后盲审通过；部署保留源码/镜像回滚点，三个生产容器的运行代码与提交一致，并通过健康检查和不发送消息的确定性探针。真实群聊行为与离线验证分开报告。
